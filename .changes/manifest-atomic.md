### Fixed

- **`.huu/manifest-<runId>.json` passou a ser escrito atomicamente.** O `flushManifest` (`src/lib/run-logger.ts`) usava `writeFileSync` direto no alvo, que **trunca o arquivo antes de escrever**. Como o flush roda a CADA fronteira de estágio — e o manifesto existe justamente para ser lido ENQUANTO o run acontece, por ferramenta externa ou por um humano acompanhando o `.huu/` — um leitor que abrisse o arquivo dentro da janela truncar→escrever via um JSON cortado no meio de um objeto. Agora a escrita vai por arquivo temporário **irmão** do alvo (`rename(2)` entre filesystems é `EXDEV`) seguido de `renameSync`: o leitor vê o manifesto anterior inteiro ou o novo inteiro, nunca um prefixo de nenhum dos dois. O nome do temporário carrega pid + aleatório, então dois runs concorrentes que compartilham o mesmo `.huu/` não colidem no staging. **O conteúdo do JSON é byte a byte o mesmo** — mudou COMO se escreve, não O QUE. Em falha o temporário é removido e o erro relançado; o `try/catch` do `flushManifest` continua engolindo tudo, porque uma falha de manifesto nunca deve derrubar um run.
