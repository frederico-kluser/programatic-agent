- [2026-08-01][source:inference][task:ci-gate-green][probation] A CI (`.github/workflows/gate.yml`, desde a 5.3.0) rodava em todo push e falhava em 100% das execuções — e ninguém percebeu, porque um sinal sempre-vermelho não distingue quebra de linha de base. As quatro causas formam um catálogo de falso-vermelho que vale reconhecer: (1) **runner sem identidade git** — a suíte cria repos git reais e commita neles, e o helper que não faz `git config` local morre em `fatal: unable to auto-detect email address`; invisível localmente porque a máquina do dev tem identidade GLOBAL. Todo teste novo que commita precisa setar a identidade no repo temporário, ou o `gate.yml` precisa setá-la globalmente (é o que ele faz agora). (2) **classificação comando-vs-caminho pela string inteira** — `[[ "$tool" == */* ]]` dá true para `npx tsx scripts/x.ts` e manda o bash procurar um arquivo com esse nome literal; classifique sempre pelo PRIMEIRO token. (3) **flag `pending` sobrevivendo ao script que ela anunciava** — qualquer `PENDENTE` força `exit 1` no gate inteiro (deliberado: gate anunciado-mas-inexistente não pode ler como verde), então o flag esquecido depois que o script nasce deixa a CI vermelha para sempre; limpe o flag no MESMO commit que liga o passo. (4) **`[[ cond ]] && cmd` como último comando de lista sob `set -e`** — retorna 1 quando a condição é falsa e mata o script; no `gate.sh` isso só disparava quando um contador era zero, ou seja, só numa execução totalmente verde: o único resultado que aquele gate nunca tinha produzido. Bug que se esconde exatamente no caso de sucesso é o mais caro de achar depois.
- [2026-08-01][source:inference][task:metodo-no-gate][probation] Ao colocar no gate um verificador de PROSA MEDIDA (números derivados do repo, como `check-metodo.ts` para o `METODO.md §1/§3`), igualdade exata é uma armadilha: todo commit move "total de linhas versionadas", então o gate fica vermelho no commit seguinte a cada atualização — e é assim que se ensina o time a ignorar o vermelho (mesma dinâmica do `PENDENTE`). Duas correções tornam o passo honesto: **tolerância relativa** (10%, `HUU_METODO_TOLERANCE`) que pega prosa materialmente errada — a tabela ficou 23% fora em dois dias — sem falhar em trabalho normal, com a mensagem citando o drift e a tolerância (METODO M2-02: asserte a MENSAGEM, não só o exit); e **cheque de cabeçalho como WARNING**, porque exigir que o commit anotado no doc seja igual ao `HEAD` é insatisfazível por construção — um arquivo não pode conter o hash do commit que o introduz (e a CI clona raso, então validar contra o histórico também não é garantido). Regra geral: antes de ligar um passo no gate, pergunte "isto é satisfazível no commit seguinte?"; se a resposta for não, o passo é aviso, não erro. Terceiro achado: o verificador comparava `src/` contra TS+TSX enquanto o documento declarava "inclui client JS/CSS/HTML" — emitia um WARN permanente, e aviso que nunca sai é ruído que se aprende a pular.
- [2026-09-05][source:inference][task:dockerfile-buildkit-portability][probation] **O gate tem 10 passos, não 9** — `check-dockerfile` (`npx tsx scripts/check-dockerfile.ts`) entrou depois de typecheck · test · validate-skills · check-acceptance · smoke-defaults · validate-graph · check-pins · check-twins · check-metodo. O corpo desta SKILL.md ainda diz "9 steps" e omite o novo — o consolidador deve reescrever essa linha. Dois aprendizados sobre COMO ligar um passo: (1) **não há nada a editar em `.github/workflows/gate.yml`** — a CI invoca `bash scripts/gate.sh` INTEIRO, então o registro `STEPS` é a lista única e o drift que `--list-from-ci` procura é estrutural­mente impossível para passos novos; `--list-from-ci` continua imprimindo os 5 comandos do YAML (`git config` ×2, `npm ci`, `npm run build`, `bash scripts/gate.sh`), não os passos do gate. (2) **um verificador só vale se souber dizer NÃO**: o teste de `check-dockerfile` roda o script como processo filho contra Dockerfiles de fixture e a MUTAÇÃO que ele mata é a forma com continuação de linha (`RUN \` + `\n` + `--mount=…`), que uma regex por linha deixa passar porque a primeira linha não tem flag nenhuma. Foi exatamente essa a forma usada no probe do bug real.
