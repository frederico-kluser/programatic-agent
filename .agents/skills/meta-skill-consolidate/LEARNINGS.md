- [2026-09-05][source:user][task:docs-skills-v3-backend-truth-fix][probation] A GATE CHECK THAT DERIVES ITS SEARCH TARGET FROM THE CURRENT SET CAN NEVER SAY NO. `validate-skills.sh`'s old "backend name consistency check" built its grep alternation from the kinds extracted out of `registry.ts` and then tested each hit with `grep -qxF "$ref" "$valid_kinds_tmp"` — where `$ref` came out of that same file. The intersection of the extracted vocabulary (`{deepseek,fake,jcode,mock,stub}`) with the `case` whitelist (`{pi,azure,stub,openrouter,real,fake,mock,azure-openai,azure-foundry}`) is `{stub,fake,mock}`, all valid by construction, so the `err` branch was unreachable and the script printed OK while a SKILL.md asserted `AgentBackendKind = 'pi' | 'azure' | 'stub'` for weeks. REPLACEMENT (this task): a FIXED historical vocabulary (`pi azure azure-openai azure-foundry copilot`) matched against SKILL.md bodies + catalog.md ONLY, in five unambiguous liveness shapes (name+`backend|agent|factory|session|prompt|SDK|CLI`; `backends?/<name>`; `--backend=<name>`; a quoted union member `'<name>' |`; `<name> is a real|live|only|default|current|user-facing|supported`), with a historical-framing escape (`remov|delet|no longer|not exist|gone|historic|legacy|obsolete|deprecat|former|superseded|used to|was|were|v3.0|REMOVED`) that lets a legitimate past-tense mention through. `registry.ts` is still read, but ONLY to UN-flag a name that has been re-added — the target set is never derived from it. Scoping the check to SKILL.md + catalog.md is deliberate: LEARNINGS.md is a dated append-only journal, so a 2026-06 entry describing the pi backend is a correct record, not a claim about today. Two permanent tests in `src/lib/skills-library.test.ts` pin both halves (fails on a live assertion, silent on a historical one); a mutation (`historical_kinds=""`) makes the first one red, so it is not vacuous. GENERAL RULE: any "consistency" check must be proven to REJECT a hand-built bad input before it is trusted — running it on the real library and seeing OK proves nothing.
