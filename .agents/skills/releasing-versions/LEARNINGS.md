- [2026-07-02][source:user][task:release-v5.0.0][probation] v5.0.0 (docker-only + default dial 70%) shipped. Three non-obvious release facts: (1) DIAGNOSE THE PAT BEFORE THE EXPENSIVE BUILD — an expired classic PAT gives `docker login ghcr.io` → `denied: denied`, indistinguishable from a scope problem at the login line; the fast discriminator is `curl -s -o /dev/null -w '%{http_code}' -H "Authorization: token <PAT>" https://api.github.com/user` → 401 = expired/invalid (get a new token), 200 = valid (then the `x-oauth-scopes:` header confirms `write:packages`). (2) `npm publish` EXIT CODE LIES on a retry — the first attempt here looked "interrupted" but had already published; the second attempt exited 1 with a transient `FETCH_ERROR` (network timeout) AFTER the package was live. NEVER trust the publish exit code: verify with `npm view huu-pipe dist-tags` → `latest` must equal the new version (dist-tag flip is the LAST step of a publish, so `latest==X.Y.Z` proves it fully committed) + `curl -sSI <dist.tarball>` → HTTP 200. (3) the multi-arch GHCR build was FAST (93s total) because the huu-host builder already had `network=host` (Driver Options, needed for the apt DNS workaround — the host resolves via stub 127.0.0.53 which the bridge can't reach) AND arm64 QEMU was pre-registered (`docker run --privileged tonistiigi/binfmt --install arm64`); verify both before firing (buildx inspect shows `linux/arm64` in Platforms + `network="host"` in Driver Options) or the emulated arm64 apt stage dies on DNS. Order held: both publishes BEFORE `git commit/tag/push` (npm publish never touches git, so the FETCH_ERROR left a clean tree). - [2026-07-04][source:inference][task:release-v5.2.0][probation] v5.2.0 (MINOR: kanban truth contract + host-aware RAM + SSE liveness + multi-run accounting — all additive). GHCR push EXIT-CODE TRAP: piping buildx through tail (`docker buildx build … --push 2>&1 | tail -N`) makes the shell's (and the background-task harness's) exit code that of `tail` = 0, so a `denied: permission_denied: The token provided does not match expected scopes` push FAILURE read as SUCCESS — I falsely reported "GHCR pushed, exit 0" until `docker buildx imagetools inspect …:X.Y.Z` came back EMPTY. NEVER pipe buildx when you need its status: run it UNPIPED with a trailing `echo "EXIT=$?"`, or use `${PIPESTATUS[0]}`/`set -o pipefail`, and ALWAYS confirm the push out-of-band via `imagetools inspect` (must show a manifest-LIST with both linux/amd64+linux/arm64, and `latest` digest == `X.Y.Z` digest). Re-confirmed the v5.0.0 classic-PAT rule the hard way: the ambient `gh` CLI token in this env is a FINE-GRAINED `github_pat_…` that `docker login ghcr.io` ACCEPTS (Login Succeeded) but which lacks `write:packages`, so the push is denied; only a CLASSIC `ghp_…` PAT worked. Silver lining: the buildx build CACHE survived the failed push, so the re-push after `docker login` with the classic PAT was ~90s (all layers CACHED — only export+push ran, no rebuild), i.e. a scope-denied push is NOT a wasted build.

- [2026-09-05][source:inference][task:release-v6.0.0][probation] **Prosa escrita à mão dentro de `## [Unreleased]` é DESTRUÍDA pela próxima consolidação — e a entrada anterior deste arquivo (v5.3.0, "written directly, not via `.changes/` fragments") recomenda exatamente a prática que causa a perda.** `replaceUnreleased()` (`scripts/changelog.ts:135-159`) monta o arquivo como `lines.slice(0, unreleasedIdx+1) + body + lines.slice(nextIdx)`: TUDO entre `## [Unreleased]` e o próximo `## [` é descartado e trocado pelos fragmentos de `.changes/`. Na 6.0.0 isso apagou os 8 bullets do método desenhado (`huu-devgraph-v1`) — uma feature que EMBARCA no tarball (`dist/lib/dev-graph/`, subcomando `huu graph`, canvas `/graph`) e tem seção `##` própria nas duas READMEs. Duas regras daqui em diante: (1) escreva SEMPRE em `.changes/<card>.md`, nunca direto na seção, mesmo num release "coeso"; (2) antes de consolidar, `git show HEAD:CHANGELOG.md | sed -n '<unreleased>,<próximo ## [>p'` e confira que o corpo antigo estava vazio — se não estava, ele precisa virar fragmento ou ser recolado à mão depois. **A verificação ingênua é cega a isso**: comparar a saída do `--dry-run` byte a byte com a seção resultante prova que os fragmentos entraram, e a IDENTIDADE com os fragmentos sozinhos é justamente a prova de que nada além deles sobreviveu. Só um diff contra `git show HEAD:CHANGELOG.md` pega — foi o que pegou (`git diff CHANGELOG.md | grep '^-[^-]'`, com o cuidado de que um bullet removido `- **X**` vira `-- **X**` no diff e escapa desse grep).
