### Changed

- **`~/.config/huu/config.json` agora é escrito atomicamente e nunca trava o boot** (`src/lib/api-key.ts`). `writeConfigStore` passou a escrever num arquivo temporário irmão (modo `0600`) e trocar pelo definitivo com `renameSync` — fecha a janela de truncagem no arquivo que guarda credenciais. Duas armadilhas do rename foram fechadas junto: `realpathSync` resolve o caminho antes de escrever (um symlink não é substituído por um arquivo comum) e uma escrita nunca sobrescreve um config já ilegível às cegas (um arquivo modo `000` seria destruído por uma gravação incapaz de lê-lo primeiro). `loadSetupConfig` (`src/lib/setup-config.ts`) **nunca lança**: 23 formas hostis de config (BOM, binário, aninhamento de 2000 níveis, `__proto__`, symlink em loop, `/proc/1`, arquivo modo `000`, …) degradam para os defaults em vez de trancar o usuário fora da própria aplicação no boot.
- **Um config ilegível agora é preservado, não só descartado.** Antes de uma escrita substituir um `config.json` corrompido, os bytes originais são copiados verbatim (nunca re-encodados como string, para não corromper mais ainda um binário) para `config.json.corrupt-<ISO>-<pid>`, modo `0600`, no máximo 3 cópias com dedupe por conteúdo — o usuário é avisado em stderr, com o caminho, nos dois idiomas. Se a cópia falhar, a gravação acontece assim mesmo: a cópia é forense, e travar o boot por causa dela seria pior do que só perder um arquivo que já estava ilegível.
- **Validade agora faz parte de "setup completo".** Um `_setup` meio-escrito (versão desconhecida, `interface`/`runtime` fora do enum, `completed` não-`true`) reabre o fluxo de setup em vez de bootar silenciosamente a interface ou o runtime errados — `isSetupComplete()` é a checagem única que `npm start` consulta.

### Removed

- **Um apagamento de credencial adormecido, fechado antes de ficar alcançável.** Ligar a persistência do setup ao boot tornaria alcançável um caminho que já existia sem uso: `readConfigStore()` degradava um JSON inválido para `{}`, e a próxima gravação por qualquer chamador descartava esse arquivo ilegível — inclusive credenciais que ainda estivessem legíveis como texto dentro do JSON truncado. A gravação do setup seria a primeira depois de uma corrupção, disparando sem aviso; o funil de escrita único (`writeConfigStore`) agora cobre `saveApiKey`, `_pools` e `_setup` juntos com a preservação acima, então nenhum chamador pode redescobrir esse buraco sozinho.
